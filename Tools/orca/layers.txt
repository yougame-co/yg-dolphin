# Orca layer map: which layer every path in the tree belongs to.
#
# Read by Tools/orca/layer-of-diff and Tools/orca/forbidden-calls (shared code in layerlib.py,
# tests in test_layers.py). Crowd fixes are routed and gated by the layers their diff touches.
#
# Line format:   <class>  <glob>  [dev] [review]
#
#   class  One of four, from least to most risky:
#          game-data         Data a game bundle will carry: profiles, .patches, JIT seeds, label
#                            textures, test inputs. Once bundles boot (S4) a change is a mod
#                            version, not an Orca release.
#          game-logic        C++ that knows one game's memory (Brawl rev 2, Project+): stage flows,
#                            rules, results, name tags, the match block layout. It moves into
#                            Orca/Games/<game>/ (S2) and becomes a script, then a mod version (S7).
#          engine            Game-agnostic: Dolphin, rollback, the session, host-only UI, tools.
#                            Always an Orca release; the perf gate if it touches the frame path.
#          engine-sensitive  Engine code a person reviews first: parsers of peer, network, app or
#                            file bytes (rooms, keyframes, replays, direct links, chat, the embed
#                            channel, profiles, patches, fonts, textures); sockets, HTTP, TLS,
#                            crypto; the compatibility key, disc and SD checks and forced settings;
#                            persistent formats (NAND and saves, savestates, settings, shader-cache
#                            keys); build inputs that pull in code (Externals, root CMake);
#                            entitlements; release scripts; and this map and its scanners.
#   glob   A path from the repository root. `*` and `?` stay inside one path segment, `**` spans
#          any number of segments, `{a,b}` lists alternatives, `[...]` is a character class.
#   dev    The path never ships in an Orca build (docs, tests, tools). layer-of-diff leaves dev
#          paths out when it decides whether a change needs an Orca build, but still reports and
#          gates on their layer.
#   review Game logic that carries competitive policy (ranked rules, what a room rates): it ships
#          as game logic, but a person reviews the diff (layer-of-diff lists it under "review").
#
# The most specific rule wins: the one with the most literal (non-wildcard) characters. Two
# matching rules with the same count and different classes or flags are an error (test_layers.py
# checks every tracked path). Every path in Orca's own code must be matched by a rule other than
# the `**` fallback, so a new area is classed on purpose, not by default.
#
# A gate runs the stable branch's copies of these tools (a checkout of origin/main) against the
# branch with --repo, and reads this map with --rules-rev: a branch that edits the map or a tool
# can't run its own copy through the gate (the tools refuse when the running copy differs from the
# rev they are told to trust).
#
# Directives (one per line, starting with %):
#   %orca-root <dir/>       Orca's own directories (besides every file that differs from upstream).
#   %upstream-ref <ref>     Upstream Dolphin; Orca's changes are the diff from the merge-base.
#   %upstream-base <sha>    The merge-base to use when <ref> is not fetched in this clone.
